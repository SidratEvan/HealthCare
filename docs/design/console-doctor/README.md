## Integrated experience

The hospital-branded shared header and session figures sit above one consultation workspace: compact read-only chamber queue, unmistakable pinned patient/serial/allergy/save status, authorised history, six numbered record sections and persistent Save Draft / Sign & Next. Desktop has queue/history/record columns; tablets use the shared queue drawer, and portrait stacks history and record while retaining patient identity and actions. Contextual bilingual Help, language switching, keyboard focus, validation, print and the existing 30-minute delay confirmation operate on the real APIs.

Custom follow-up accepts Bangla or Latin whole days **1–365**, in addition to none/7/14/30. Calculation starts from the Bangladesh calendar day, independent of device timezone. The existing API accepts date-only strings; `follow_up_date` already has a database lower bound at the visit's Bangladesh creation day (`0007_clinical.sql:86`), with no 365-day upper bound. No backend restriction, endpoint or migration was added. An acknowledged/reviewed date remains fixed in sign confirmation, its signing attempt and server-record print. Invalid input blocks signing; draft save persists the other valid notes with **null follow-up**, explicitly discloses the exclusion/clearing, and retains the invalid text locally. Switching away from that text requires explicit discard. No appointment or reminder is created.

Signing reviews the pinned encounter and clinical content. It makes no prediction of a named next patient. Its confirm button becomes unavailable if the live queue changes, while the note remains bound to the original patient. Saving, not saved, saved, excluded follow-up, failed/uncertain and signed states are distinct. Failed/uncertain draft requests must be reconciled before signing. Record and queue receipts remain separate and truthful.

## Prototype comparison and retained safety

The approved `doctor-v1` prototype was read without modification. Its branded header, session bar, compact queue, patient strip, paired history/record workspace, numbered sections, tablet drawer, persistent actions and sign review are integrated through Batch 1 components/tokens. Production retains real empty/loading/error states and longer safety copy. V1's own prescription fields and draft-time test orders remain; prototype simulation, auto-saving, fabricated vitals and predicted next-person state are not imported. The queue is read-only: Reception retains its queue responsibilities. Delay remains exactly 30 minutes.

Batch 4A's [C1/C2 contract](../console-doctor-safety/README.md) and backend/API/database code are unchanged. The encounter-owned controller, revision hydration/conflict checks, frozen identity/body/key, synchronous repeat guard, stale-response rejection and authoritative receipts still own all writes. External Next keeps the original patient panel and notes. Explicit save/discard/review precedes switching. A lost signature is retried with its original attempt, including after queue movement; a different immutable signature preserves this device's conflicting text. Failed lab orders retain the original booking/codes/key even after switching. Printing still reads the persisted record. Clinical fields are not stored in browser persistence or the offline outbox.

Patient-code redemption uses existing hospital scope, expiry, consent and audited records APIs. Protected views are keyed to the edited encounter and close when it changes. The existing V1 code can authorise the named patient independently of the current booking; its records identify that patient. No clinician-account linking or permission widening was added.
